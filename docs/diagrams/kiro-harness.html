Kiro IDE and Kiro CLI — one agent harness

Flow

  1. 1You type in the IDE chat or the CLI; both are clients of the same harness.
  2. 2Local clients talk to the harness over the Agent Client Protocol (JSON-RPC over stdio), with Kiro-specific _kiro/ extensions for steering, specs, permission prompts and context tracking.
  3. 3Prompt, history, steering and the active spec are always loaded; skills and powers load on demand; Prompt Submit hooks run.
  4. 4The request goes to the chosen model or the Auto router. Kiro is powered by Amazon Bedrock with cross-region inference (US or EU profile).
  5. 5Every tool call is checked against permission rules (deny > ask > allow) and kiroignore; Pre Tool Use hooks can block it.
  6. 6Allowed tools run; shell commands can run inside the local OS sandbox (Seatbelt or bwrap). Post Tool Use hooks run and results feed back into the loop.
  7. 7MCP tools reach local (stdio) or remote servers, loaded on demand with tool search.
