Flow

  1. 1A person writes in the dashboard, a channel thread or the CLI.
  2. 2Channel senders must pass the owner lock first.
  3. 3HookManager → HookManager (auto-reply, transform, deny)
  4. 4The key encodes the origin: channel thread, dashboard slot, cron job, subagent or task step.
  5. 5SessionManager → Context assembly (assemble)
  6. 6SessionManager → ACP client (prompt + context)
  7. 7JSON-RPC 2.0 over stdio to kiro-cli acp, warm or cold process.
  8. 8kiro-cli acp → Kiro service (LLM) (inference)
  9. 9kiro-cli acp → ACP client (request_permission)
  10. 10Deny rules, sensitive paths and the POLICY ∩ PROFILE ceiling; decisions are written to the hash-chained security event log.
  11. 11Built-in tools run in the OS sandbox; MCP tools go through the pooled MCP gateway daemon.
  12. 12SessionManager → SessionManager (append JSONL, consolidate memory (async))
